raea 0.1.6 makes the app you work in every day lighter and quicker. Its window now holds its memory through a long day, and drafts finish sooner. Claude and voice now work on a new Mac without setting anything up. A note you send while your agent works goes into the turn it's on, and the command it's running keeps going. Films play smoothly in the timeline and stop at their end. Long chats open in a moment, with their older messages folded by when you had them. Export is one window, each project has a Review tab, and every comment you leave reaches the agent.

**Get the app at [raea.io](https://raea.io)** (a Mac with Apple silicon, Windows 10 or 11, or Linux on x86_64).

The engine alone:

```sh
curl -fsSL https://raea.io/install | sh
```

On Windows, in PowerShell: `irm https://raea.io/install.ps1 | iex`.

## What changed since 0.1.5

**The window holds its memory.** The app's JavaScript kept the memory it had finished with, so an hour's work grew it from 272 MB to 448 MB while what it actually held stayed near 60 MB. It now gives that memory back every few seconds and stays near 166 MB.

**The window rests.** With nothing changing on screen, raea's window now waits for you instead of drawing the same picture 60 times a second, and it wakes on the next key, click, answer or timer. Each frame's small steps now run on one thread instead of waking a pool of workers for each: 34% less CPU at rest, 8% less in a drag, 4% less playing a film, with frames as quick as before. To go back to the old way, put `RAEA_ST=0` or `RAEA_IDLE_GATE=0` in `~/.raea/env`.

**Drafts finish sooner.** A draft render in the app no longer runs the clipping check after its last frame, which took about a fifth of a second on a 3D draft. Renders your agents make keep the check.

**Claude and voice work on a new Mac.** In 0.1.5, picking Claude did nothing unless Claude Code was already installed, and voice never downloaded what it needs. Now raea installs Claude Code, or Kimi Code, with its maker's own installer when it isn't there, and shows the download in onboarding's bar. The first press of the mic sets voice up, parakeet-mlx and then its 2.3 GB model, showing in the composer what it's getting and how far along it is.

**Slash commands work.** `/goal` typed as a new chat's first line now sets the goal, where it used to go to the agent as words. The agent's own commands and skills, like `/compact`, run as commands instead of being answered as text. The box names a command once you've written it, and says when a /word isn't one of the agent's. In the chat a command is a line of its own, Running… then Ran. / and @ open their search anywhere a word starts with them, not only at the start of the box.

**Your agent keeps its project while you're elsewhere.** An agent working in one workspace while you had another open, or another chat, could lose its project: a card it posted wasn't kept and its plan tools said it had none. Now its cards, plan and items stay in its own project whichever workspace is open.

**Agents finish what they plan.** A task can't be marked done with a box unticked or a subtask open: the plan tools refuse it and name what's open, and closing with everything ticks and closes it all. Each time an agent stops with tasks of its own still open, raea asks it to settle them.

**You can see where a message is.** A message sent while the agent works shows in the thread at once as waiting, with Send now and Take back (its words back in the box); the latest says Sending… then Delivered. A note sent from an item shows in the chat beside the feed, which switches to the chat it went to.

**Films play smoothly in the timeline.** The playhead moves with every frame instead of four times a second. An edited film plays across a split without stopping to seek, and never shows a frame a cut removed. A film under the timeline stops on its last frame instead of looping back to the start. A seek while it plays shows nothing from where it was, and a film played again from its end starts at its start.

**Notes reach your agent while it works.** Send a message, or a note from a chat's pictures, while the agent is busy and it goes into the turn the agent is on, between its steps. A command it's running keeps going; nothing is stopped or killed to make room. Each note is its own message in the thread. An agent that can't take a message mid-turn gets everything that waited as one message when its turn ends. The composer's button sends whenever there's something in the box, and is Stop only when the box is empty, so a press meant to send never stops the agent.

**Every comment reaches the agent.** Nothing you write on an agent's work is left behind as a note it never sees: it waits for that agent and goes with your next send. Edit now edits a comment's words, and Send sends one on its own. Esc closes an open comment before it leaves Comment, and scrolling inside a comment scrolls the comment instead of zooming the picture under it. A post of plain words has Copy.

**What's running is what's running.** The line over the composer counted every shell a chat had ever left in the background, so it could say 39 running when nothing was. It now goes by the agent's own word: a shell, a monitor or a subagent shows while it runs and goes when it ends, and nothing left from before the agent restarted, or before the app reopened, counts.

**Renders show how far they've got.** While something renders in a chat's project, a meter over the composer fills as its frames finish.

**Move a chat to another project.** Drag a chat from the header, or from its list of sessions, onto a project in the rail, or pick Move to in its menu. It carries on there, its agent working in the new project's folder. Archiving a chat whose agent is still at work now asks whether to stop it too; Stop and archive ends its turn and everything it left running.

**Long chats open fast.** raea reads a chat's history from its end, a stretch at a time, and leaves pictures and long tool output on your Mac instead of in the window. The longest chat on our test Mac, 264 MB on disk, now opens with 3.4 MB in under a fifth of a second. Your last six messages are open. Older ones fold into sittings, a new one after an hour's pause, on a new day or every eight of your messages, each one row saying when it began, how many messages it holds and how you opened it. Click one to open it and everything after it; scroll to the top and the stretch before comes in, keeping your place.

**Export, in one window.** Export in an item's header opens one window: Save as…, Download (straight into Downloads), Show in Finder, and a tile for each network saying whether the film fits its shape and length. Export again makes a smaller copy of any film, or another shape or quality of one made from a composition; copies sit beside the film. Stills, sounds and models have Download, or Download all when there are several.

**A Review tab in every project.** Where Controllers was, Review lists the project's review links (views, notes, approval) and its work to share, newest version of each piece, with the ones tagged final first. Pick pieces and raea makes one link and copies it. Agents can mark a piece final when they post it. Controllers are still there, under Source.

**Getting around.**
- With more than one chat in a project, up to three sit in the header. Pin a chat to keep it there. A project inside this one with an agent working shows its mark with a light; the parent project is one press away.
- The rail opens wide from its foot, with every name beside its mark, and stays that way.
- A project with projects inside it lists their tasks in its Tasks, each under its project's name, and their files, compositions and components in its Source.
- A project can open chat first or feed first. Feed first gives the work the window and puts the chat in the right panel (⌘\ shows and hides it). Set it in Edit project or the project's menu.

**Fingerprint › Rules.** A Rules tab lists every "A standing rule?" question raea asked that you haven't answered, and the rules an agent added, each with why; keep or drop each in a click. Your own rules, each workspace's house rules and each project's own are a tree, and each rule says when it applies, what checks it and how the fingerprint learns it. Write a rule of your own, or turn a note raea is watching into one. Agents read, add and check rules, and a fingerprint score in a chat is a line of its own instead of being folded into "Used raea".

**Fewer controls on every view.** Every view's controls were gone through again, and repeats cut. A film has one ⋯ menu, its time without the total, Share as an icon and Compare in the version menu. The film editor loses its Select arrow and the made-up "Scene N" tags on clips. The composition editor's bar goes from 15 controls to 8.

**Agents can report a bug in raea.** `raea bug TITLE --text TEXT` sends a report to raea, from a terminal or from the app's agents (bug_report). It sends words only, with paths, emails and anything shaped like a key taken out first, and needs no account. `--dry-run` prints exactly what would go.

**Fixed.**
- An item whose details named something the app didn't expect could leave the whole window black on opening.
- A first launch could make its workspace twice at once.
- A project you renamed went back to its old name when the app started again.
- In raea's window, the volume popover shut as the pointer moved into it.
- A picture attached to a note, and a library's posters on Publish, drew as empty boxes in raea's window.
- A panel opened after something was posted into it while it was closed showed an empty row.
- On the Mac, a window manager such as AeroSpace couldn't see a raea app's window.

**For builders.**
- `<Screen app>` draws a whole app on a surface in your 3D scene, on a page of its own: click and type into it through the 3D in a live play. A play's log keeps what reached it, so `raea render --input` draws what was played, and an exported game takes its app screens along.
- A batch of stills renders each frame at its own time. Since 0.1.1, every still in a batch sampled `globals.time` 0 and drew the first frame's `<Material>` uniforms.
- `raea render --aov` and `RAEA_PASS` work with MSAA on; they failed after two frames.
- An `<R3F>` scene lit by `PMREMGenerator.fromScene(new RoomEnvironment())` is lit by that room, and an object scaled to 0 draws nothing, as in three.
- raea's window: a scroll offset a page writes reads back as written, `getComputedStyle` reads colours and custom properties, and a page's own `/host/*` images and fonts load.
- The R3F guide says when to set three's ambient light to 0 by hand: raea's own ambient lights a scene's specular as well, so a scene ported as-is comes out washed.
- The sound guides teach composing music for the cut, never a default bed, with every vetted source and its licence one page away.

**Known**
- A seek while a film plays in the timeline can show one frame from before the seek (about 33 ms) before it jumps.
- Timeline playback still passes over frames on a heavily loaded Mac, and a cut still waits for its seek's decode.
- A long 4K `raea render` can still hang before its first frame (#158).
- On a laptop with both AMD and NVIDIA graphics, the Windows app can crash at launch; set `WGPU_BACKEND=dx12` (#155).
- Characters (the Character SDK: bodies, faces, hair, sewn clothes, hands) moved to 0.1.7.
- R3F's pointer input has no double click yet, and touches don't arrive as pointers.
- In TSL compute, Points and Sprites don't read compute buffers, indirect dispatch isn't supported, a compute first dispatched after frame 0 doesn't run, and a texture or matrix uniform in a compute isn't supported.
- A render in layers for CapCut, Premiere and Resolve is planned (docs/layers.feature, from @wackyza), not built.
- postprocessing's Outline, TextureEffect, DepthEffect and LUT1D, and TSL's OutlineNode, are skipped, with one warning that names them.
- The Windows app is unsigned, as before: Windows asks once whether to run it.
- A proxy set by an automatic configuration (PAC) file isn't read. If yours uses one, start raea with `HTTPS_PROXY` set.
